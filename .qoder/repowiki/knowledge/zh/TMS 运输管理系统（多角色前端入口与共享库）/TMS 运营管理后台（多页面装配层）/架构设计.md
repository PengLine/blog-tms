本模块由三层协作构成：
- 数据层 `tms-store.js`：基于 `localStorage` 的轻量数据库，负责种子数据生成、实体 CRUD、订单全生命周期状态流转（pending→inbound→sorted→shipping→arrived→delivering→signed），并在每次变更时派发 `tms:datachange` 事件。
- UI 层 `tms-ui.js`：提供 `table/formModal/modal/confirm/toast/kpis/charts/detailModal/timeline/initShell` 等通用组件，所有 DOM class 以 `tms-` 前缀隔离样式。
- 页面装配层 `tms-pages.js`：集中 `define('exception'|'transport'|'warehouse'|'vehicle'|'capacity'|'material'|'service'|'claim'|'finance'|... )` 注册每个业务页的配置（title/subtitle/kpis/table.toolbar/actions），由 `TmsPages.render(id)` 渲染出标准骨架并订阅 Store 变更自动刷新。

跨子模块的耦合点：
1) 所有业务子模块（hr_user_management、finance_claims、material_warehouse、transport_sorting、monitoring_geofence、operations_performance、administration_support）对应的 HTML 模板仅承担静态骨架，实际交互逻辑集中在 `tms-pages.js` 中按 `id` 分发；新增页面只需在 HTML 末尾 `<script>TmsPages.render('<pageId>')</script>` 并调用 `S.createXxx()/S.updateXxx()` 写入 Store。
2) 跨实体关联通过订单号 `orderId` 串联：异常→理赔、运输→扫描记录、签收→财务流水均由 Store 内部方法（如 `advanceOrder`、`addScanRecord`、`ensureSortingTask`）自动维护。
3) 导航栏异常待办角标由 `initShell` 统一读取 `exceptions` 列表计算并注入 `.nav-badge`，是跨页面可见的全局状态。
