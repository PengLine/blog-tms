- 页面通过 `TmsPages.define('<pageId>', { title, subtitle, kpis, table })` 声明式注册，而非各自编写渲染逻辑。
- 数据读写统一走 `global.TmsStore` 的 `list/create/update/remove`，禁止直接操作 `localStorage`。
- UI 渲染统一使用 `TmsUI.table/formModal/modal/confirm/toast/statusBadge`，所有 class 名以 `tms-` 前缀命名避免冲突。
- 实体 ID 采用带业务前缀的自增序列（EX/TR/SV/CLM/FIN/INV/VEH/CAP/GF/POL/RUL/ADDR/TMR/CHG/KPI/EV/EMP/SRT/LOD/SC/user/role/perm/dept），由 Store 的 `counterNext` 生成。
- 状态值遵循 `STATUS_LABELS` 字典中的枚举键（order/exception/transport/ticket/claim/finance/employee/vehicle/inventory/capacity/policy/gateway），标签与颜色由 `statusBadge` 统一映射。
- 跨实体联动（异常闭环创建理赔、运输完成触发财务收入、订单推进写入扫描记录）在 Store 的业务方法内实现，页面侧只调用高层 API。
